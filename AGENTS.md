# AGENTS.md

This repo deploys the UCCC cBioPortal instance on onclappc02. Read `README.md` first. It has the
layout, the runbook and known gotchas, and this file doesn't repeat them.

## This is a live service

The checkout on onclappc02 *is* the production deployment. It serves
https://uccc-cbioportal.cancerdatasci.org from a 193 GB ClickHouse database that takes about
1.5 h to reload. Other apps share the host.

Ask before running any of these:

- `docker compose down -v`, `docker volume rm`, or anything else that touches the pinned volumes
  `cbioportal-docker-compose_cbioportal_{clickhouse,mongo}_data`
- `just load-dump` against a database that isn't empty
- `just import` for a study that's already loaded: `-o` overwrites live base tables mid-import (#8)
- `just derive-tables` or `just restart`: both cause downtime
- changes to the Traefik labels or `tailscale serve`

Read-only commands are always fine: `just check`, `just logs`, `docker compose ps`, and
`clickhouse client` `SELECT`s.

## Editing rules

- Don't edit the vendored upstream files (`docker-compose.yml`, `entrypoint.sh`, `config/init.sh`,
  `data/*.sh`, `LICENSE`). Put UCCC changes in `docker-compose.override.yml` or
  `config/uccc.properties`.
- `config/uccc.properties` holds only the keys we change. Don't copy the whole
  `application.properties` into it.
- `config/application.properties` and `data/*.sql*` are generated by `just config`. Regenerate them;
  don't hand-edit them.
- Add tasks as `just` recipes, not ad hoc scripts or a Makefile.
- If you find a new gotcha, add it to the README's Gotchas section with the upstream issue number
  when one exists.

## Host quirks (onclappc02)

- umask is 027, so files git writes are mode 640. Any file bind-mounted into a container that runs
  as a non-owner uid, such as the logo or `uccc.properties`, needs `chmod o+r`, or the container
  can't read it.
- Use `/data/davsean/tmp` for scratch, not `/tmp`. The parquet dump defaults to
  `/data/davsean/tmp/cbioportal` (`CBIO_DUMP_DIR`).

## Secrets

`.env` is gitignored and holds `CLICKHOUSE_PASSWORD`. Never commit it, print it, or paste it into
issues or PRs. New settings go in `.env.example` with a placeholder value.

## Workflow

- Planned work lives in GitHub issues (`gh issue list`). Use issue → branch → PR, and reference
  the issue in the PR.
- Before you call a deployment change done, run `just check`. It should show the API healthy,
  551+ studies and schema `3.1.0`. If you changed the UI, check it in a browser too.
